# Аудит готовности сайта «ПитерМебель»

Дата проверки: 12 сентября 2026 года.

## Итог

Критические технические и содержательные ошибки, которые можно было исправить без выдумывания данных владельца, устранены. Проект собирается в production-режиме, а локальный browser QA проходит по всем 38 маршрутам из sitemap в desktop- и mobile-размерах.

Сайт ещё нельзя считать полностью готовым к приёму реальных заявок и публикации точной цены: нужны ключ сервиса форм, подтверждённые реквизиты оператора персональных данных и правила преобразования параметров мебели в спецификацию.

## Что показала таблица `просчет.ods`

Таблица содержит одну подробную спецификацию, а не универсальный прайс. В ней есть стоимость материалов и фурнитуры, коэффициент производства `1,92` и контрольные итоги одного заказа: материалы `162 056,40 ₽`, итог `355 463,12 ₽`, варианты на 6 и 12 месяцев `391 009,43 ₽` и `408 782,58 ₽`.

Из неё нельзя достоверно вывести цену по одной только длине кухни: отсутствуют нормы, которые переводят планировку и метры в количество листов, площадь фасадов, петли, ящики, столешницу и работы. Поэтому значения сохранены только как контрольный пример в `data/calculator-pricing.ts`, а публичная цена отключена.

## Нужны данные владельца

1. Access Key Web3Forms и адрес получателя заявок.
2. Решение по CAPTCHA/Turnstile после теста спама; скрытый honeypot уже есть, но один он не является достаточной защитой.
3. Юридический статус, полное имя или наименование оператора, ИНН, ОГРН/ОГРНИП и юридический адрес.
4. Подтверждённые сроки хранения заявок, список сервисов хранения и решение по обработке данных через внешний Web3Forms.
5. Проверка необходимости уведомления Роскомнадзора и первичной записи персональных данных в РФ.
6. Для точной цены — базовые комплектации и нормы расхода отдельно для кухни, шкафа и корпусной мебели; правила углов, острова, фасадов, механизмов, монтажа и доставки.

## Проверки

- `npm run build` — успешно, 43 статические страницы сгенерированы.
- `npm run test:smoke` — успешно: 38 маршрутов в desktop/mobile, один H1, отсутствие горизонтального переполнения и битых изображений, внутренние ссылки, мобильное меню, URL калькулятора, синхронизация формы, отсутствие ложного успеха заявки.
- `npm audit --offline --omit=dev` — известных уязвимостей в локальной базе npm не найдено.
- Yandex SEO toolkit — robots без ошибок, sitemap без ошибок, 37 URL; в исходном HTML главной не обнаружены числовые цены-кандидаты.
- `git diff --check` — должен выполняться перед коммитом; переносы строк Windows могут выводить информационные предупреждения, но не являются ошибкой контента.

## Оставшиеся ограничения

- Реальную доставку письма нельзя проверить до добавления ключа Web3Forms.
- Юридический текст является аккуратным рабочим каркасом, но не заменяет проверку юристом после заполнения реквизитов и схемы обработки данных.
- `npm run lint` пока запускает устаревший интерактивный `next lint`: ESLint и конфигурация в проекте отсутствуют. Установка пакетов в этой сессии не выполнялась; production-сборка и TypeScript-проверка проходят.
- Файлы `brand/brand_info.json`, `site_dataset.json`, `EXPORT_REPORT.md` и старые концепт-стили являются архивом прежнего исследования и содержат исторический адрес на Трефолева. Они не входят в публичную сборку; источником актуальных фактов должны считаться `client_data/` и `DESIGN_LOCK.md`.
- После публикации нужно отдельно проверить реальные HTTP-заголовки, Метрику, цели, карту, доставку писем и индексацию в Яндекс Вебмастере.
