# Контракт Direction v12

Direction проверяет не наличие трёх HTML, а пригодность направлений для осознанного выбора. Этап нельзя завершать на заглушках, трёх вариациях одной композиции, длинных псевдосайтах без craft или самооценке автора.

## 0. Pre-design readiness

Direction — первая стадия, на которой создаётся дизайн. До первого concept HTML должны одновременно быть готовы:

- подтверждённый `BRIEF.md`;
- прошедший Research с выбранными фрагментами и `SYNTHESIS.md`;
- для `PROJECT_MODE: COMMISSIONED` — `SOURCE_READINESS: COMPLETE`, source registry, полная доступная доказательная база, клиентский media pack и brand audit;
- либо явный `CLIENT_SOURCE_WAIVER.md` пользователя с точным перечнем принятых пробелов.

Client Intelligence и Reference Research не заменяют друг друга. Если клиентский сборщик ещё работает, Research можно закончить, но Style Lab не запускается. Ошибка `PRE_DESIGN_NOT_READY` блокирует создание концептов, а не всю цель.

## 1. Медиа до концептов

До Style Lab собери реальные разрешённые изображения проекта в:

- `.design/media/project-media.json` — `{ "media": [{ "path": "public/images/…", "source": "…", "usage": "…" }] }`;
- `.design/media/project-media-board.png` — визуальная проверка набора.

Для клиентского демо сначала используй материалы клиента из разрешённого пользователем источника. Если их недостаточно — добавь лицензированные стоки с зафиксированными URL. Скриншоты референсных сайтов не являются контентом проекта.

Stock обязан совпадать с предметом показа. Интерьер может демонстрировать композицию и кадрирование, но случайная мастерская, станок или ремесленник не может играть proof производства, если это не подтверждено клиентом. Подпись `demo stock` не превращает нерелевантный кадр в доказательство.

Каждый concept HTML использует минимум два разных файла из manifest. `PHOTO SLOT`, геометрические заглушки вместо предмета продажи и обещание «фото добавим позже» — hard-fail. Если разрешённых изображений нет, остановись со статусом `MEDIA_REQUIRED`.

## 2. Гипотезы из Research, а не меню стилей

До контрактов открой в полном размере `SYNTHESIS.md`, `FRAGMENTS.md`, fragment PNG и, если клиентский источник доступен, `CLIENT_SOURCE.md` вместе с `brand-source-board.png`. Если существует `.design/REJECTED.md`, это обязательный вход: не повторяй отвергнутые композиционные семьи и приёмы.

Существующий бренд — отдельный вход, а не пятый референс. Для каждого направления зафиксируй `brandTreatment`: какие подтверждённые сигналы сохраняются, как они применяются в новой системе и какие разовые эффекты старых обложек сознательно не переносятся. При `PRESERVE` нельзя менять знак и базовую палитру без разрешения; при `EVOLVE` узнавание сохраняется, но старый рекламный layout не копируется; `REFRESH` не разрешает автоматически перерисовывать логотип; при `NOT_ESTABLISHED` направление не должно выдумывать фирменную историю.

Не задавай заранее три архетипа вроде «кинематографичный / редакционный / материальный». Название появляется после гипотезы. Гипотеза отвечает на вопрос: **какое наблюдаемое отношение между медиа, текстом и действием из Research поможет именно этому бизнесу?** Разные прилагательные не создают разные направления.

Каждому направлению назначь 2–4 fragment ID. Один fragment поддерживает только конкретное отношение: масштаб медиа относительно тезиса, смену плотности, порядок действия, структуру выбора или поведение mobile. Нельзя ссылаться на сайт целиком словами «вдохновились атмосферой».

Если fragment PNG не дают трёх действительно разных и продуктово уместных гипотез, не компенсируй пробел модельными архетипами. Остановись со статусом `REFERENCE_GAP`, перечисли недостающие отношения/поверхности и верни работу на точечное расширение Research; весь Research с нуля для этого не нужен.

## 3. Контракты трёх направлений

До HTML создай `.design/style-lab/DIRECTION_CONTRACTS.json`:

```json
{
  "concepts": [
    {
      "id": "concept-1",
      "designQuestion": "какой вопрос о восприятии и маршруте проверяет направление",
      "archetype": "наблюдаемая модель страницы",
      "compositionFamily": "буквальное описание skeleton без стилевого ярлыка",
      "sourceFragments": ["F01", "F05"],
      "sourceTransfers": [
        {
          "fragment": "F01",
          "observedRelation": "что буквально видно на fragment PNG",
          "transfer": "какое отношение переносится в concept",
          "mutation": "как перенос изменён под brief и реальные media"
        }
      ],
      "heroGeometry": "геометрия и положение главного медиа",
      "navigationModel": "поведение и композиция навигации",
      "contentRhythm": "ритм секций и смена плотности",
      "mediaRole": "что фотографии доказывают и как кадрируются",
      "typeSystem": "роли display/body/utility и характер иерархии",
      "colorStrategy": "роль фона, текста и акцента",
      "signatureElement": "один специфический приём, связанный с продуктом",
      "brandTreatment": "что из подтверждённой идентичности сохраняется/эволюционирует и что из разового оформления не переносится"
    }
  ]
}
```

Нужно ровно три концепта. Для каждой пары должны различаться `compositionFamily` и минимум пять из семи осей: `heroGeometry`, `navigationModel`, `contentRhythm`, `mediaRole`, `typeSystem`, `colorStrategy`, `signatureElement`.

`sourceFragments` между концептами могут пересекаться максимум одним ID. На каждый заявленный fragment нужна ровно одна конкретная запись в `sourceTransfers`. Если перенос нельзя показать рядом на PNG, удали ссылку: она декоративная.

Разные названия при одинаковой сетке, огромном заголовке, вертикальном рельсе, hairline-таблицах и цветовых заменах не считаются разными направлениями.

Каждый HTML — компактный system sampler примерно на 2–4 desktop viewport, а не полная 6–8-тысячепиксельная главная. Он показывает header+hero+transition, representative listing/project, representative detail/proof и CTA; mobile перестраивается отдельно. Полные страницы создаются только на Page Targets.

## 4. Визуальная трассировка

После capture создай `.design/style-lab/reference-trace-board.png`. Для каждого concept на одной видимой группе расположи:

- 2–4 использованных fragment PNG;
- desktop-first и mobile-first concept PNG;
- короткие подписи `fragment → перенесённое отношение`.

Это основной тест работы с референсами. `DIRECTION_CONTRACTS.json` без этого борда доказывает только способность написать объяснение.

## 5. Независимое сравнительное ревью

После одной craft-итерации передай read-only reviewer `BRIEF.md`, `SYNTHESIS.md`, `FRAGMENTS.md`, fragment PNG, media board, contract JSON, reference-trace-board и реальные concept PNG в полном масштабе. Добавь `.design/REJECTED.md`, если он существует. Автор концептов не может сам выдать `independent`-вердикт. Если отдельный reviewer недоступен, остановись для пользовательской оценки.

Reviewer сохраняет `.design/style-lab/DIRECTION_REVIEW.json`; если клиентская идентичность доступна, reviewer отдельно проверяет `brandFit`, а не только сходство с референсами:

```json
{
  "reviewerMode": "independent-read-only",
  "evidence": [".design/style-lab/shots/…png"],
  "referenceEvidence": [".design/research/fragments/F01-….png"],
  "concepts": [
    {
      "id": "concept-1",
      "observedStrength": "наблюдаемая сильная сторона на кадре",
      "observedWeakness": "наблюдаемый риск или дефект",
      "referenceFit": "какое source→output отношение действительно видно или не видно",
      "brandFit": "сохраняется ли подтверждённое узнавание без буквального копирования старой обложки",
      "genericityRisk": "какой AI-default или повтор отвергнутого решения замечен; none только с объяснением",
      "verdict": "advance"
    }
  ],
  "recommended": "concept-1",
  "weakest": "concept-3",
  "sharedMotifs": ["повторяющийся приём, замеченный между концептами"],
  "decision": "READY_FOR_USER_SELECTION"
}
```

Допустимые verdict: `advance`, `rework`, `reject`. Нельзя принять все три: минимум одно направление получает `rework` или `reject`. `recommended` и `weakest` обязаны различаться. Направление без наблюдаемого reference fit или повторяющее мотив из `REJECTED.md` не может получить `advance`. Числовые оценки запрещены.

Гейт Direction запускается до показа пользователю. `GATE_PASS` означает только, что доказательства и честное сравнение на месте; окончательный визуальный выбор остаётся за пользователем.
