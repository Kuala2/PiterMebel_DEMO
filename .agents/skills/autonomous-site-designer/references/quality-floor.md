# Quality floor: что делает результат профессиональным

Три слоя: принципы композиции, именованные запреты, машинные проверки. Первые два проверяются по скриншотам на каждом дизайн-этапе, третий — скриптом `audit.mjs` на QA (обмануть его нельзя, лучше не попадаться).

## Принципы

1. **Signature element.** По умолчанию на странице одна смелая идея — необычная сетка, крупное кадровое решение, один orchestrated reveal, — а всё остальное тихо. Больше одной смелой идеи — редкое осознанное решение, а не норма. «Не рискнуть — тоже риск»: результат без единой смелой идеи — шаблон.
2. **Hero — постер, а не документ.** Первый экран: бренд + один заголовок + одна фраза + одна CTA-группа + одно доминирующее изображение. Убери навбар — страница всё ещё должна быть узнаваемо «твоей» (тест бренда).
3. **Одна работа на секцию.** Каждая крупная секция отвечает на новый вопрос клиента и содержит визуальный центр: реальное медиа, сравнение, данные, инструмент. Однотонная плоскость с заголовком — не секция.
4. **Mobile — отдельная композиция.** Не сжимай desktop: свой crop фото, свой порядок блоков, свой ритм. Главный CTA в первом мобильном viewport, не переносится на две строки.
5. **Реальный контент.** Никакого lorem ipsum. Неизвестные факты — явные `[поля]`. Копирайт: конкретика лучше остроумия; кнопки называют результат («Получить расчёт», а не «Отправить»).

## Именованные запреты (AI-slop бан-лист)

**Шрифты:** Inter, Roboto, Open Sans, Lato, system-ui/Segoe запрещены как identity/display-шрифт — на них нельзя строить характер проекта. Как нейтральный служебный UI/body-шрифт они допустимы, только если характер несёт осознанный display-шрифт и это явно записано в токенах. Любые гарнитуры без кириллицы (Space Grotesk, Bebas Neue…) запрещены всегда.

**Паттерны.** Каждый — с причиной, почему запрещён:
- фиолетово-синий градиент на белом — дефолт №1 любой генерации;
- glassmorphism (blur-карточки) без реальной слоистой логики;
- иконка над заголовком в карточке — универсальный tell фичевой карточки;
- eyebrow-плашка/чипс над каждым заголовком;
- hero-metric layout (огромная цифра + подпись + 3 статы + градиент);
- одинаковая сетка карточек там, где нужна иерархия; карточки там, где карточка не является интерактивной единицей;
- боковые акцентные полоски на карточках;
- гигантский тонкий заголовок на пустом фоне как «дизайн»;
- бежевый #F4F1EA + серифный display + терракотовый акцент — клише 2025–26;
- декоративные blur-блобы, случайные градиентные «формы»;
- split-hero «фото слева, текст справа» как единственная композиционная идея;
- видео/WebGL-эффект как единственный носитель впечатления.

Замена запрещённого — не «сделать иначе ради иного», а вернуться к секции: какой вопрос клиента она закрывает и что здесь визуальный центр.

**Новое поле максимума:** если заметил, что два проекта подряд используют один и тот же «смелый» приём — это новый дефолт, смени его.

## Машинные проверки (audit.mjs, этапы Targets/Build/QA)

Жёсткие (P0): горизонтальный скролл на 320/360/390/430/768/1440; пустая страница; нет непустого h1; JS-ошибки; dev-overlay. Всегда блокируют.
Важные (P1): контраст ниже WCAG (4.5:1 текст / 3:1 крупный, считается с альфа-смешением); цели нажатия < 44px на mobile; img без alt; иконки-кнопки без aria-label; кнопки с переносом текста; нет `:focus-visible`; битые картинки; console.error; HTTP ≥ 400 same-origin. Блокируют release, если пользователь явно не принял их в `.design/qa/WAIVER.md`.
Замечания (P2): >1 h1; нет `<main>`/`lang`; текст < 15px; межстрочный < 1.35; строки > 90 симв.; генерик-подписи кнопок; анимации без `prefers-reduced-motion`.

## Визуальные hard-fail (по скриншотам, все дизайн-этапы)

- обрезанный или наложенный текст; текст, вылезающий за контейнер;
- CTA или смысл страницы не видны в первом мобильном viewport;
- нечитаемая навигация поверх реального hero-фото;
- пустая центральная зона без доминирующего объекта;
- элемент выглядит интерактивным, но не работает (или наоборот);
- случайный crop прячет предмет продажи;
- две соседние крупные секции с одинаковой композицией и одной задачей;
- все страницы — один и тот же шаблон с другим текстом.
- `PHOTO SLOT`, серый/цветной прямоугольник или абстрактная геометрия вместо реального предмета продажи;
- три Direction-концепта повторяют одну грамматику (тот же hero, гигантский заголовок, hairline-таблицы и перестановка цвета), даже если у них разные названия;
- направление объясняется словом «редакционное», «кинематографичное», «материальное», «архивное» или другим стилевым ярлыком, но на source→output борде не видно переноса конкретного отношения из fragment PNG;
- giant-type + вертикальный индекс/рельс + hairline-таблицы используются как готовый комплект характера, если этот комплект не доказан выбранным референсом и задачей продукта;
- демонстрационный stock изображает неподтверждённое производство, мастера или технологию клиента; подпись `demo` не превращает нерелевантный кадр в доказательство;
- видимые пользователю `[CTA]`, `[поле]` или служебные пояснения подменяют нормальный демо-копирайт; неизвестный факт остаётся полем в документации, но интерфейс использует честное нейтральное действие без выдуманного обещания;
- автор концептов сам объявляет свой review независимым или «принимает все три» без сравнения сильнейшего и слабейшего.

Приёмка — только по real screenshots в читаемом масштабе (first/full/сегменты), не по миниатюрам борда и не по описанию замысла. Формулируй наблюдаемое: «заголовок в 2 словах на строку в колонке 280px», а не «плохо смотрится».
