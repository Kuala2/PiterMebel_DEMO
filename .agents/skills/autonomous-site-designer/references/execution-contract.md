# Контракт выполнения для разных агентов

Этот skill описывает результат и проверяемые переходы, а не названия инструментов конкретной модели. Codex, Gemini, GLM/ZCode и другие coding agents выполняют один контракт через доступные им эквиваленты.

## 1. Определи активный этап

1. Явно названный пользователем этап имеет приоритет.
2. `Возобнови` означает: изучи существующие `.design/`-артефакты, запусти гейт предполагаемого последнего этапа и продолжи с первого непрошедшего перехода. Не пересоздавай прошедшие артефакты без наблюдаемой причины.
3. `С нуля` означает не использовать старые дизайн-артефакты как вход. Не удаляй их без разрешения: создай чистую рабочую область или сначала зафиксируй точные файлы, которые будут заменены.
4. Если запрос ограничивает работу этапом или точкой остановки, это жёсткая граница. Не продолжай автоматически после PASS.

## 2. Сопоставь возможности среды

Используй доступный эквивалент по назначению:

| Возможность | Назначение |
|---|---|
| web/search | получить актуальные URL и факты |
| interactive browser/computer use | увидеть динамическую страницу, cookies и пользовательскую сессию |
| shell/terminal | запустить scripts и гейты |
| image viewer/vision | оценить полноразмерные PNG, а не описания |
| isolated reviewer/subagent | независимое read-only сравнение, только если среда реально поддерживает его |

Не останавливай этап из-за отсутствия инструмента с конкретным названием, если есть эквивалент. Не объявляй собственное ревью независимым. Если обязательной возможности нет и эквивалента нет, выдай точный статус (`SOURCE_UNAVAILABLE`, `MEDIA_REQUIRED`, `REVIEWER_REQUIRED`) и сохрани уже готовые артефакты.

## 3. Управляй контекстом

- Всегда прочитай этот контракт и раздел активного этапа в `stages.md`.
- Остальные references загружай только когда этап на них ссылается.
- Большие machine-отчёты сначала фильтруй скриптом/поиском; изображения открывай выборочно в полном размере.
- Факты пользователя и текущие файлы выше старых отчётов. Не считай текст предыдущего агента доказательством без артефакта.

## 4. Выполняй переход артефактами

Для каждого этапа порядок одинаков:

1. проверить входные артефакты;
2. создать только выходы текущего этапа;
3. открыть визуальные доказательства самостоятельно;
4. запустить соответствующий `gate.mjs`;
5. при `GATE_FAIL` исправить перечисленные причины один пакетный раз;
6. повторить гейт и остановиться в заданной контрольной точке.

`GATE_PASS` подтверждает структуру и доказательства, но не объявляет дизайн красивым. Визуальный выбор делает пользователь в предусмотренных checkpoint-ах.

## 5. Формат передачи результата

Сообщи: статус этапа; созданные артефакты; наблюдаемые ограничения; что требуется от пользователя одним коротким действием. Не пересказывай весь процесс и не скрывай частичный результат общим словом `blocked`.
