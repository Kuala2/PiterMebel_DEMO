# Reference Scout v9

Цель — не отчитаться о процессе, а дать дизайн-агенту папку с реальными скриншотами, из которой видно, как устроены хорошие сайты в этой нише. Быстро: весь этап должен занимать десятки минут, а не часы.

## Канонический источник

- Не копируй этот skill из другого проекта и не синхронизируй его вручную. `Site demo/.agents` — архив и не является источником.
- При вызове из `autonomous-site-designer` соблюдай его stage boundary и возвращай артефакты Research, не переходя к Direction.

Прочитай перед работой:
- [references/execution-contract.md](references/execution-contract.md) — всегда первым: переносимый порядок для Codex, Gemini, GLM/ZCode и других агентов;
- [references/discovery.md](references/discovery.md) — где и как искать;

`<root>` — папка этого SKILL.md. Команды выполняй из корня проекта (там же должен стоять playwright: `npm i -D playwright && npx playwright install chromium`).

## Непереговорные правила

- Референс = живой сайт с реальным скриншотом. URL из памяти модели запрещён; каждый сайт должен быть реально открыт.
- Используй возможности среды по назначению, а не требуй инструмент с конкретным названием. Без визуального просмотра реальных PNG кандидат не принимается.
- Начни с 20–30 реальных URL, но не превращай это в 20–30 глубоких исследований. Поиск и интерактивный браузер дают дешёвый инвентарь; стандартизированный захват делается только для 8 лучших кандидатов. География и тип источника — метаданные, а не квоты финального пула. Слабый сайт нельзя оставить ради локальной, международной, craft или curated ячейки.
- Захвати главную 8 кандидатов (desktop + mobile, `"pageType": "home"`). Остановись на `board-pool` и получи короткий пользовательский выбор. Только после него для 4 финалистов захвати 2 внутренние страницы (desktop, `"pageType": "inner"`, `"mobile": false`). Формат `sites.json`:
  ```json
  [{"name":"studio-x","url":"https://studio-x.ru/","pageType":"home","mobile":true},
   {"name":"studio-x-works","url":"https://studio-x.ru/works","pageType":"inner","mobile":false}]
  ```
- Захват делает только `capture.mjs` — его machine-отчёт `captures.json` проверяется гейтом research (финалисты обязаны иметь ok-захват home + внутренней + mobile).
- Если сайт заблокировал headless — один повтор, затем обычный интерактивный browser среды, если он есть; если нет — замени кандидата. Блокировка сайта не является кризисом и не останавливает работу.
- Не выдумывай факты о сайтах. Всё, что записано про скриншот, должно быть на нём видно.
- Скриншоты референсов — визуальная опора, а не контент будущего сайта.

## Процесс

1. Прочитай `.design/BRIEF.md` (если его нет — сначала этап brief основного скилла). Определи 2–3 поверхности, которых не хватает нише: например hero, listing, detail, mobile.
2. Найди кандидатов по [discovery.md](references/discovery.md). Сохрани поисковый инвентарь и причины отсева в `.design/research/DISCOVERY.md`, а итоговую восьмёрку — в `.design/research/POOL.json`. Сохрани `sites.json` только с восемью кандидатами и сними их home desktop+mobile:
   ```bash
   node <root>/scripts/capture.mjs urls --list sites.json --out .design/research/references
   ```
3. Открой полученные PNG сам и собери `board-pool`. Запусти `gate.mjs --stage research-pool`, покажи доску пользователю и **остановись**. Пользователь не ищет URL и не пишет дизайн-бриф: достаточно отметить кандидатов как `approved`, `rejected` или `neutral`, либо отклонить весь пул. Запиши ответ в `.design/research/POOL_SELECTION.json` по формату из discovery.md. Без этого файла глубокий Research не продолжается.
4. После решения `continue` выбери 4 финалиста не по сумме абстрактных баллов, а на четыре взаимодополняющие роли:
   - `visual-anchor` — сильный многостраничный сайт той же ниши; задаёт цельность home/listing/detail/mobile;
   - `product-system` — сайт той же ниши или смежного физического продукта; даёт каталог, detail, материалы и работу фотографии;
   - `art-direction` — самый сильный источник отличительного визуального механизма; он может быть из той же ниши, соседнего продукта или curated, но не выбирается ради происхождения;
   - `commercial-ux` — локальный сайт той же ниши; даёт оффер, доверие и сценарий заявки.
   Чисто архитектурных/портфолио сайтов среди финалистов может быть не больше одного, если сам проект не относится к архитектуре. Кандидат с пользовательским статусом `rejected` не может стать финалистом. Для каждого финалиста добавь 2 внутренние страницы (`mobile:false`) и создай `FINALISTS.json` по формату из discovery.md.
5. Напиши `.design/research/REFERENCES.md`: по одной секции `## <сайт>` на финалиста (роль, URL, **Источник** — где найден; чем доказал пользу на home и внутренних страницах, что берём, что не берём). Кратко: 4–6 строк на сайт. Если `visual-anchor` силён только одним первым экраном, он не финалист.
6. Собери доску фрагментов по [fragments.md](references/fragments.md): 8–12 кропов в `.design/research/fragments/` + `FRAGMENTS.md`.
7. Собери честные борды для просмотра пользователем — только из machine-отчёта захвата:
   ```bash
   node <root>/scripts/board.mjs --captures .design/research/references/captures.json --page-type home --variant desktopFirst --out .design/research/board-pool.png --cols 4
   node <root>/scripts/board.mjs --captures .design/research/references/captures.json --page-type inner --variant desktopFirst --out .design/research/board-finalists-deep.png --cols 4
   node <root>/scripts/board.mjs .design/research/fragments --out .design/research/board-fragments.png --cols 4
   ```
   `board-pool` — только первые desktop-экраны главных страниц; внутренние страницы показывай отдельным `board-finalists-deep`. Запрещено собирать `board-pool` передачей всей папки `references`: там лежат и mobile, и inner, и evidence-кадры, и пользователь перестаёт понимать, где настоящий первый экран.
8. Свяжи фрагменты с будущими поверхностями в `.design/SYNTHESIS.md` (это делает основной скилл; если вызываешь scout автономно — просто убедись, что фрагменты подписаны).

## Проверка

До Direction проверь быстрый Reference Fit без генерации сайта: может ли `visual-anchor` доказать цельность на home/listing/detail/mobile; есть ли минимум два продуктовых/медийных фрагмента; не сводится ли весь набор к волоскам, огромной типографике и пустым полям. Если среда умеет изолированные subagent-ы, отдай три борда read-only reviewer. Один цикл замены слабого финалиста допустим; рекурсивный поиск запрещён. Никаких числовых оценок и вердиктов «красиво/некрасиво» без наблюдаемых причин.

## Остановка

У Research теперь две остановки. Первая: только `board-pool`, до глубокого захвата. Вторая: `board-finalists-deep`, `board-fragments`, REFERENCES.md и SYNTHESIS.md перед Direction. Если пользователь отклонил весь пул, разрешён один новый поиск с учётом наблюдаемой причины; рекурсивные замены запрещены. Если живых сильных сайтов нашлось меньше 4 — остановись и скажи об этом честно, вместо того чтобы добирать мусор.
