# Discovery: где искать живые референсы

## Маршрутизация инструментов

Не выбирай браузер наугад и не смешивай обнаружение сайта с его приёмкой:

1. **Веб-поиск** — только для получения настоящих URL по запросам ниши и города. Сниппет и позиция в выдаче не доказывают качество.
2. **Интерактивный видимый браузер среды** — для быстрого просмотра поисковой выдачи, curated-витрин и страниц, которые требуют JS, согласия cookies или обычной пользовательской сессии. Здесь агент решает, стоит ли сайт добавлять в `sites.json`.
3. **`capture.mjs`/Playwright** — обязательная стандартизированная съёмка каждого кандидата и внутренних страниц финалистов. Только эти PNG являются доказательством для отбора.
4. **PNG-борды** — финальное сравнение. Не выбирай финалиста по памяти после живого просмотра: вернись к `board-pool` и `board-finalists-deep` и сравни одинаковые viewport рядом.

Если интерактивного браузера в среде нет, discovery можно выполнить веб-поиском, но кандидат всё равно не принимается без чистого захвата `capture.mjs`. Если сайт нельзя чисто снять после лестницы отказа — замени его.

## Поисковый инвентарь: 20–30 URL

Основной канал по умолчанию — обычная коммерческая выдача Google/Яндекса. Логика пользователя разумна: компании с бюджетом на SEO, рекламу и бренд чаще имеют как минимум рабочие коммерческие сайты. Но позиция в выдаче повышает вероятность полезного кандидата, а не заменяет просмотр реального экрана.

Собирай инвентарь последовательно, останавливаясь, когда уже есть 8 сильных кандидатов:

1. 8–12 URL из локальных коммерческих запросов: `<продукт> на заказ <город>`, `<продукт> премиум <город>`, `<категория> по индивидуальным размерам <город>`.
2. 4–8 URL из национальных запросов без города и из соседних крупных городов. Это расширяет конкуренцию, но не создаёт квоту для финала.
3. Если среди них не хватает визуального разнообразия — 4–6 URL из релевантных кейсов веб-студий и профильных галерей с обязательным переходом на оригинальный сайт.
4. Только если остаётся конкретный пробел — 2–4 URL из соседней физической ниши: кухни, двери, свет, камень/поверхности, интерьерные системы, премиальная недвижимость. Для каждого заранее назови искомый механизм: например material navigator, проектный архив или подача вариантов продукта.

Не перебирай все каналы ради ритуала. Если прямые конкуренты дали сильную и разнообразную восьмёрку, дополнительные источники не обязательны.

В `.design/research/DISCOVERY.md` сохрани 20–30 URL, запрос/источник и одно короткое решение: `screen` или `reject` с наблюдаемой причиной. Из них 12–16 быстро просмотри в интерактивном браузере. Стандартизированный Playwright-захват делай только для финальной восьмёрки.

## Финальный пул: без географических квот

`POOL.json` содержит ровно 8 кандидатов. Для каждого нужны: `name`, `domain`, `url`, `sourceType`, `sourceDetail`, `observedFirstViewport`, `observedMobile`, `internalRoutes` (минимум 2 URL) и `transferableMechanism`.

Кандидат проходит только если на реальном просмотре:

- первый viewport имеет ясный визуальный центр и иерархию;
- mobile намеренно перекомпонован, а не обрезает desktop;
- существуют минимум две содержательные внутренние страницы;
- есть один конкретный переносимый механизм;
- сайт соответствует аудитории или решает явно названный проектный пробел;
- он не является почти точным дублем другого кандидата.

Страна, известность бренда, награда, позиция в поиске и принадлежность к curated-галерее не являются пропуском сами по себе.

## Product/Craft как дополнительный канал

Сильные многостраничные сайты смежных физических продуктов с похожим способом выбора: материалы, свет, мебельные системы, сантехника, кухни, двери, предметный дизайн. Чистая архитектурная студия допустима как один кандидат, но не должна вытеснять продуктовые сайты только из-за красивой сетки.

Ищи наблюдаемое качество, а не отрасль: `architecture studio case study`, `material brand editorial product detail`, `interior studio project archive`.

## Curated как дополнительный канал

Сильный art direction. Работающая техника — «витрина как визуальный каталог», одним визитом:

1. **Один визит на URL за прогон.** Витрины живо реагируют на повторы: SiteInspire на повтор отдаёт Vercel security-checkpoint, Awwwards — промо-интерстишел вместо каталога. Поэтому первый и единственный заход делай сразу `capture.mjs urls` — за один визит получишь и скриншот витрины, и до 300 ссылок из неё (в `captures.json`, поле `links`; ссылки из меню помечены `inNav`).
2. Посмотри скриншот витрины глазами и выбери 2–4 карточки по превью (как делает живой дизайнер), затем найди их URL в `links` (у SiteInspire карточки ведут на страницу-детализацию, с неё оригинал — внешняя ссылка; у Awwwards карточки — `/sites/…`). Названия на превью сопоставляй с текстом ссылок; если превью без названия и непонятно, какая ссылка его открывает, — не угадывай, возьми другую карточку.
3. Каждую страницу-карточку тоже бери одним визитом `capture.mjs urls` — внешняя ссылка на оригинальный сайт будет в её `links`. Карточка не открылась (checkpoint/промо): один заход через интерактивный browser среды, если он есть; не помогло — замени карточку другой. Никаких ретраев по кругу.
4. Если на скриншоте вместо витрины промо/чекпойнт — источник на этот прогон выгорел. Не ретрай тот же URL: возьми другую категорию или другой источник. Машина не отличит каталог от красивой рекламной заглушки на том же домене — верь глазам по скриншоту, не статусу «ok».

Проверенные источники (снимок на август 2026, headless; доступность волатильна — HTML, чекпойнты и региональные ответы могут измениться в любую неделю, «доступен в этом запуске — используем, недоступен — быстро заменяем»): **SiteInspire** — категории открываются, превью рендерятся (`/websites/category/architecture`, `design-and-art-direction`, `portfolio`, `grid-layout`, `unusual-layout`); **Awwwards** — `/websites/` и подкатегории открывались первым визитом; статьи-подборки («best … websites» на Dezeen, Creative Bloq и т.п.) — обычный текстовый fetch. **Land-book** — 403 для headless: только через интерактивный browser среды, если он есть, иначе пропусти. Галерея — способ найти ссылку; референсом является оригинальный сайт.

## Практика блокировок

- Headless-захват получил bot-challenge → один повтор → интерактивный browser среды, если есть → иначе замени кандидата. Это нормальный ход работы, не авария.
- Галерея закрыта Cloudflare → просто не используй её. Смени источник, а не упорствуй.
- Никогда не автоматизируй решение CAPTCHA.
- Редирект на другой домен → зафиксируй финальный домен и пересними.

## Hard reject до захвата

- Маркетплейс, каталог тем, SEO-статья, шаблон.
- Одностраничник без внутренних страниц (для финалистов нужны 2 внутренние).
- Эффект, живущий только на WebGL/видео, который нельзя перенести.
- Почти точный дубль уже взятого кандидата.
- Сайт, выбранный только из-за известного бренда.
- Сайт, у которого сильный только hero, а listing/detail/mobile распадаются или отсутствуют.
- Второй чисто архитектурный craft-финалист для неархитектурного коммерческого проекта.

## Формат FINALISTS.json

Ровно четыре роли и четыре уникальных домена:

```json
{
  "finalists": [
    {
      "name": "brand-x",
      "domain": "brand-x.com",
      "role": "visual-anchor",
      "lane": "market",
      "relevance": "same-niche",
      "coverage": ["home", "listing", "detail", "mobile"],
      "observedReason": "На реальных кадрах единая работа фото, типографики и навигации сохраняется на четырёх поверхностях."
    }
  ]
}
```

Допустимые роли: `visual-anchor`, `product-system`, `art-direction`, `commercial-ux`. Допустимая relevance: `same-niche`, `adjacent-product`, `adjacent-craft`. `visual-anchor` и `commercial-ux` обязаны быть `same-niche`; `product-system` — `same-niche` или `adjacent-product`; `adjacent-craft` может быть только один. `art-direction` не обязан приходить из curated/craft: роль описывает вклад, а не происхождение. Coverage у каждого финалиста содержит `home`, `listing`, `detail`, `mobile` и подтверждается захватами, а не названием поля.

## Формат POOL_SELECTION.json

Агент записывает короткий ответ пользователя, пользователь JSON не редактирует:

```json
{
  "source": "user",
  "decision": "continue",
  "approved": ["brand-a.ru", "brand-b.com"],
  "rejected": ["brand-c.com"],
  "neutral": ["brand-d.com", "brand-e.com", "brand-f.com", "brand-g.com", "brand-h.com"],
  "note": "Нравятся первый экран A и каталог B; C слишком галерейный."
}
```

Три списка вместе покрывают все 8 доменов пула без повторов. Для `continue` нужен хотя бы один `approved`. Если пользователь отклонил всё, `decision` = `replace-pool`, глубокий Research не начинается; разрешён один новый пул.

## Минимум ceremony

Не создавай JSON-контрактов ради контрактов. Один `sites.json` на вход capture, machine-отчёт `captures.json` на выходе capture и один `REFERENCES.md` с источником находки каждого сайта — этого достаточно. Всё, что ты пишешь о сайте, должно быть видно на его скриншоте.

Осторожно с SEO-подборками «best <niche> websites»: это источник ссылок, а не оценка качества — каждый сайт из подборки проверяй по его собственному скриншоту, а не по месту в списке.
