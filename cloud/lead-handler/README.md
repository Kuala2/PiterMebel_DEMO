# Приём заявок через Yandex Cloud

Основной вариант, выбранный владельцем 29.09.2026. Подключение отложено; в этом этапе обновлены только документы и сведения о планируемых обработчиках. Ресурсы облака не создавались.

Код подготовлен для Cloud Functions (`nodejs22`, точка входа `index.main`). Сайт остаётся статическим: форму нельзя включать, пока не настроены российское хранение заявок, доменный маршрут и сведения об обработке данных. Текущий `canReceiveLeads` в `data/legal.ts` оставлен выключенным.

## Что делает обработчик

- Принимает только POST `multipart/form-data` с `Origin: https://pitermebel.com` и телом до 12 КБ. Это дополнительная проверка, а не защита от подделанного запроса.
- Проверяет поля и версию согласия, сохраняет его утверждённый текст из настроек функции, а также проверяет скрытые поле `website` и галочку `confirm_order` **на сервере**. Бот, заполнивший любую ловушку, получает нейтральный ответ без сохранения заявки.
- Ограничивает до трёх новых заявок с одного номера телефона за 10 минут. Для ограничителя хранится только HMAC номера с секретным ключом. Это не заменяет капчу при массовом спаме с разными номерами.
- Сохраняет заявку, серверное время, редакцию и полный неизменяемый текст согласия в YDB Serverless. `submission_id` предотвращает повторную запись при повторной отправке.
- Затем отправляет письмо через Cloud Postbox. При сбое почты заявка остаётся в YDB, браузер получает ошибку; повторная отправка с тем же ID пытается отправить письмо ещё раз. Записи со статусом `pending` нужно контролировать в YDB и разбирать вручную, если посетитель не повторил попытку. При сбое отметки об отправке после успешной доставки возможен повтор письма; сверяйте ID заявки.
- Устанавливает `expires_at` через 88 дней. TTL YDB удаляет записи не мгновенно: по документации обычно в течение двух дней; для строгого срока и обработки отзыва нужен отдельный регламент удаления и контроль всех копий, включая почту и резервные копии.

## После регистрации облака

1. Создать платёжный аккаунт и каталог Yandex Cloud в регионе Россия. Предоставить исполнителю **доступ к каталогу**, а не присылать секретный ключ в чат.
2. Создать служебный аккаунт функции с ролью `ydb.editor` для выбранной YDB Serverless и ролью `postbox.sender` для Cloud Postbox. Функция берёт временный IAM-токен из контекста; статический ключ доступа ей не нужен.
3. Создать YDB Serverless, взять **Document API endpoint**. Создать таблицу с ключом `id` (строка) и TTL по числовому полю `expires_at`. Подготовленный `setup.js` создаёт таблицу и запрашивает TTL, если заданы `YDB_DOCUMENT_ENDPOINT`, `YDB_LEADS_TABLE`, временный `YC_IAM_TOKEN` в локальном окружении. Токен нельзя записывать в репозиторий.
4. В Cloud Postbox подтвердить домен отправителя и DNS-записи, настроить адрес отправителя. Адрес получателя, например `piter.meb@yandex.ru`, подтвердить с владельцем. Проверить, что именно этот почтовый сервис и его хранение отражены в документах сайта.
5. Развернуть содержимое этой папки как функцию `nodejs22`, точка входа `index.main`, с привязанным служебным аккаунтом. Переменные функции:

   | Переменная | Значение |
   | --- | --- |
   | `LEAD_ENABLED` | `true` только после проверки всего списка |
   | `LEAD_ALLOWED_ORIGIN` | `https://pitermebel.com` |
   | `LEAD_CONSENT_VERSION` | `2026-09-29` — текущая версия `/consent/`; перед запуском сверить с `LEGAL_VERSION` в `data/legal.ts` |
   | `LEAD_CONSENT_TEXT` | точная утверждённая редакция согласия целиком |
   | `YDB_DOCUMENT_ENDPOINT` | Document API endpoint базы |
   | `YDB_LEADS_TABLE` | имя созданной таблицы |
   | `LEAD_HASH_KEY` | случайный секрет длиной не меньше 32 символов, через Lockbox |
   | `POSTBOX_FROM` | подтверждённый адрес отправителя |
   | `LEAD_NOTIFY_TO` | подтверждённый адрес получателя |

6. Настроить на хостинге сайта маршрут **`https://pitermebel.com/api/leads` → HTTPS-адрес функции** без редиректа браузера. Текущий сайт развёрнут как статический Next.js export; файл `Caddyfile` сам по себе не гарантирует настройки Timeweb App Platform. Если текущий тариф/режим Timeweb не поддерживает проксирование `/api/leads`, выбрать поддерживаемый шлюз или перенастроить размещение до включения формы.
7. Завершить `LEGAL_SETUP.md`: реквизиты оператора, обработчики, сроки, уведомление в РКН и публикация окончательной редакции согласия. ООО «Яндекс.Облако» и Яндекс Почта уже внесены в `PROCESSING_SETUP.processors` как планируемая схема; сверить её с реальными сервисами, российским размещением баз/копий и договорами. Юридический адрес провайдера не заменяет адрес размещения базы для уведомления РКН. Затем установить `approved: true`, задать `NEXT_PUBLIC_LEAD_ENDPOINT=/api/leads` при настроенном маршруте, пересобрать и опубликовать сайт.
8. Отправить тестовую заявку и проверить запись в YDB, совпадение текста/версии согласия, письмо, повторную отправку, срабатывание скрытого поля, ошибки и фактическое удаление по регламенту. Отдельно проверить, что логи не содержат телефон или текст обращения.

## Защита от спама

Обе скрытые ловушки и ограничение по телефону включены в код. Скрытая галочка не помечена как обязательная: человек её не видит и не должен отмечать.
