# Лёгкий вариант: заявки только на почту (без базы)

По решению владельца 04.10.2026: схема «форма → Cloud Functions → письмо», без YDB. Единственное место, где заявка хранится, — почтовый ящик оператора `piter.meb@yandex.ru` (Яндекс Почта). Полный вариант с базой сохранён в [../lead-handler/](../lead-handler/README.md) как альтернатива; одновременно подключать оба нельзя.

Форма отправляет заявку напрямую на публичный адрес функции (`https://functions.yandexcloud.net/<ID>`), поэтому **маршрут на хостинге настраивать не нужно** — этот формат прямо разрешён в `app/actions/measure.ts`.

## Что упростилось и что потерялось

| | Лёгкий (этот) | Полный (lead-handler) |
| --- | --- | --- |
| Ресурсы в облаке | Функция + Postbox | Функция + Postbox + YDB |
| Шагов настройки | ~4 | ~6 |
| Стоимость | 0 ₽ (в бесплатных лимитах) | 0 ₽ (в бесплатных лимитах) |
| Если почта не сработала в момент отправки | Заявка потеряна, посетитель увидит ошибку и может повторить | Заявка осталась в базе |
| Лимит «3 заявки с номера за 10 минут» | Нет (только скрытые ловушки от ботов) | Есть |
| Доказательство согласия | Версия и время в письме + опубликованная редакция `/consent/` | Полный текст согласия в базе |

Совсем «без хранения» нельзя: письмо в ящике — уже хранение персональных данных, и 152-ФЗ требует хранить подтверждение согласия. Этот вариант законен, но следствие: **письма нужно удалять по сроку** (в полном варианте за это отвечала база). Договоритесь с владельцем о сроке (в документах сайта заявлено 90 дней) и периодически чистите ящик; ящик должен быть в Яндексе (данные в РФ).

## Настройка в консоли Yandex Cloud (console.yandex.cloud)

1. **Биллинг и каталог** (если ещё нет): «Биллинг» → создать биллинг-аккаунт, привязать карту. На главной — «Создать каталог», имя `pitermebel`. Всё ниже — внутри этого каталога.
2. **Сервисный аккаунт**: левое меню «Сервисные аккаунты» → «Создать сервисный аккаунт» → имя `lead-mailer-sa`, роль **`postbox.sender`** → «Создать».
3. **Postbox**: левое меню «Postbox» → «Создать адрес» → домен `pitermebel.com`, DKIM «Простая» → «Создать адрес». Появятся **две CNAME-записи** — добавить их в DNS-панели Timeweb («Домены» → DNS-записи), дождаться статуса «Success» на странице адреса (до суток; кнопка «Запустить проверку»). Адрес должен быть в том же каталоге, что и сервисный аккаунт. Записать выбранный адрес отправителя (например `zayavki@pitermebel.com`).
4. **Функция**:
   - собрать ZIP (PowerShell, из папки `cloud/lead-mailer`):
     ```powershell
     Compress-Archive -Path index.js -DestinationPath function.zip -Force
     ```
   - левое меню «Cloud Functions» → «Создать функцию» → имя `lead-mailer`;
   - среда выполнения **`nodejs22`**, точка входа **`index.main`**, таймаут **15 с**, память 128 МБ, сервисный аккаунт `lead-mailer-sa`, загрузить `function.zip`;
   - переменные окружения:

     | Имя | Значение |
     | --- | --- |
     | `LEAD_ENABLED` | `true` |
     | `LEAD_ALLOWED_ORIGIN` | `https://pitermebel.com` |
     | `LEAD_CONSENT_VERSION` | `2026-09-29` (сверить с `LEGAL_VERSION` в `data/legal.ts`) |
     | `POSTBOX_FROM` | адрес из шага 3 |
     | `LEAD_NOTIFY_TO` | `piter.meb@yandex.ru` |

   - «Создать версию», затем на вкладке «Обзор» включить **«Публичный доступ»** и скопировать ссылку `https://functions.yandexcloud.net/<ID>`.
5. **Проверка напрямую** (Git Bash, заменить `<ID>`):
   ```bash
   curl -s -X POST "https://functions.yandexcloud.net/<ID>" \
     -H "Origin: https://pitermebel.com" \
     -F "submission_id=7e2b9c1a-3d4f-4e5a-9b8c-1d2e3f4a5b6c" \
     -F "Телефон=+79001234567" \
     -F "Тип мебели=Консультация" \
     -F "Пожелания=Тестовая заявка" \
     -F "consent=true" -F "consent_version=2026-09-29" \
     -F "consent_document=/consent/" \
     -F "consent_client_at=2026-10-04T12:00:00Z" \
     -F "website=" -F "confirm_order="
   ```
   Ожидаемо `{"success":true}` и письмо на `piter.meb@yandex.ru`. Повторный вызов с тем же `submission_id` придёт вторым письмом (дубли не отслеживаются — это осознанное упрощение). Если письма не доходят — создать в Postbox идентификатор адреса получателя (подтверждение по ссылке из письма) и/или запросить у поддержки продакшн-режим.
6. **Включение на сайте** — только после юридической части (`LEGAL_SETUP.md`, уведомление РКН): в `data/legal.ts` поставить `PROCESSING_SETUP.approved = true`, при сборке задать `NEXT_PUBLIC_LEAD_ENDPOINT=https://functions.yandexcloud.net/<ID>`, пересобрать и опубликовать сайт, отправить тестовую заявку с самой формы.

## Правки в подготовленных документах при этом варианте

- Уведомление РКН ([docs/RKN-INSTRUCTION-YANDEX-CLOUD-2026-10-04.md](../docs/RKN-INSTRUCTION-YANDEX-CLOUD-2026-10-04.md)): раздел «База заявок YDB» не заполняется — из мест хранения остаются Яндекс Почта (запросить у неё адреса площадок по договору) и журналы Timeweb. В цели «заявка с сайта» из состава данных исчезает «технический идентификатор ограничения повторных отправок» (хеша больше нет), остальное совпадает. Запрос в поддержку Яндекс Cloud сокращается до Cloud Functions + Postbox.
- `PROCESSING_SETUP.processors` в `data/legal.ts`: оставить ООО «Яндекс.Облако» (функции) и ООО «ЯНДЕКС» (почта) — состав уже верный.
- Формулировка «хранение заявки в базе до 88 дней» из полного README не применяется; срок удаления писем назначает владелец и соблюдает вручную.
