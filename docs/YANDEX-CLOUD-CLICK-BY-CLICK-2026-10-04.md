# Yandex Cloud: подключение заявок по шагам (куда нажимать)

> **Лёгкий вариант (04.10.2026, по решению владельца):** заявки только письмом, без базы YDB и без маршрута на хостинге — это ~4 шага вместо 7. Инструкция: [cloud/lead-mailer/README.md](../cloud/lead-mailer/README.md). Этот документ описывает полный вариант с YDB — он остаётся как запасной, если лёгкого окажется мало (защита от потери заявок и лимита спама).

Схема уже выбрана и подготовлена 29.09.2026: форма сайта → Cloud Functions → YDB Serverless → Cloud Postbox → `piter.meb@yandex.ru`. Код обработчика готов в `cloud/lead-handler/`. Этот документ — версия «для клика» с точными кнопками консоли; технические обоснования и полный чек-лист — в [cloud/lead-handler/README.md](../cloud/lead-handler/README.md).

Всё делаем в одном каталоге облака (это важно: Postbox и сервисный аккаунт должны быть в одном каталоге). Стоимость: при малом потоке заявок останемся в бесплатных лимитах — **0 ₽/мес**.

Консоль: **console.yandex.cloud** → вход через аккаунт Яндекса.

---

## Шаг 0. Биллинг и каталог (если ещё нет)

1. Верхняя панель → выбрать облако. Если облака нет — «Создать облако», имя `pitermebel`.
2. **Биллинг**: в левом меню → «Биллинг» → «Создать биллинг-аккаунт» → тип «Оплата по факту» → привязать карту. Без биллинг-аккаунта ресурсы не создадутся.
3. **Каталог**: на главной кнопка «Создать каталог» (или при создании облака) → имя `pitermebel` → «Создать».
4. Всюду ниже: сначала открываем этот каталог (переключатель каталога в верхней панели), потом сервис в левом меню.

## Шаг 1. Сервисный аккаунт (от имени функции будут доступ к YDB и почта)

1. В каталоге левое меню → **«Сервисные аккаунты»** → кнопка **«Создать сервисный аккаунт»**.
2. Имя: `lead-handler-sa`.
3. Блок «Роли в каталоге» → добавить **две** роли: `ydb.editor` и `postbox.sender`.
4. «Создать».

Статический ключ не нужен — функция берёт временный IAM-токен автоматически.

## Шаг 2. База YDB Serverless

1. Левое меню каталога → **«Базы данных»** (сервис YDB) → **«Создать базу данных»**.
2. Тип: **Serverless**. Имя: `pitermebel-leads`. Регион: `ru-central1`. Создать.
3. Дождаться статуса **«Running»** (несколько минут).
4. Открыть базу → вкладка **«Обзор»** → скопировать поле **«Document API endpoint»** (вида `https://docapi.serverless.yandexcloud.net/ru-central1/…`). Сохраните — это переменная `YDB_DOCUMENT_ENDPOINT`.

### Создание таблицы

1. Внутри базы слева **«Навигация по объектам»** → **«Создать таблицу»** (в новом интерфейсе: «Обозреватель»/«Навигация» → «+ Создать» → «Таблица»).
2. Имя таблицы: `leads`.
3. Колонки:
   - `id` — тип **String**, отметить **«Ключевая колонка»** (первичный ключ);
   - `kind` — тип **String**;
   - `expires_at` — тип **Uint64** (любой числовой).
   Остальное обработчик дописывает сам — Document API не требует объявлять все поля.
4. В диалоге — блок **TTL (Time to Live)**: включить, атрибут **`expires_at`**, единица **«секунды»**. Если блока нет — открыть созданную таблицу → «Изменить таблицу» → настроить TTL там.
5. «Создать таблицу».

Проверка TTL по шагам 88 дней настраивается в коде (`expires_at`), в базе ничего дополнительно менять не нужно.

## Шаг 3. Postbox (почта для уведомлений)

1. Левое меню каталога → **«Postbox»** → кнопка **«Создать адрес»**.
2. Домен: `pitermebel.com` (или полный адрес отправителя, например `zayavki@pitermebel.com` — тогда именно его указываем потом в `POSTBOX_FROM`).
3. Блок «Настройка подписи писем (DKIM)» → «Простая» → «Создать адрес».
4. На странице адреса появится блок **«Настройка подписи писем (DKIM)»** с **двумя CNAME-записями**.
5. Добавить обе CNAME-записи там, где сейчас DNS-зона `pitermebel.com` (по чек-листу Timeweb зона в панели Timeweb: «Домены» → DNS-записи → «Добавить запись» → тип CNAME, скопировать имя и значение из блока DKIM).
6. Вернуться на страницу адреса в Postbox и дождаться статуса **«Success»** (DNS обновляется до суток; кнопка «Запустить проверку» — если долго).
7. Идентификатор в Postbox должен быть создан **в том же каталоге**, что и сервисный аккаунт — иначе при отправке будет ошибка.

Квота по умолчанию — 200 писем в сутки; для заявок с сайта этого достаточно (одно письмо на заявку). Если письма на `piter.meb@yandex.ru` не доходят — создать в Postbox идентификатор для адреса получателя (подтверждение по ссылке из письма) и/или запросить через поддержку перевод в продакшн-режим.

### Создать функцию в консоли

1. Левое меню каталога → **«Cloud Functions»** → **«Создать функцию»** → имя `lead-handler` → «Создать».
2. Откроется редактор версии. Заполнить:
   - **Среда выполнения**: `nodejs22`;
   - **Точка входа**: `index.main`;
   - **Таймаут**: `20` секунд (обработчик делает несколько запросов к YDB и почте подряд);
   - **Память**: 128 МБ (по умолчанию);
   - **Сервисный аккаунт**: `lead-handler-sa`;
   - загрузить **function.zip** (кнопка «Загрузить файл»).
3. Блок **«Переменные окружения»** — добавить по одной (кнопка «Добавить переменную»):

   | Имя | Значение |
   | --- | --- |
   | `LEAD_ENABLED` | `true` — на время проверки; окончательно оставить после полного чек-листа README |
   | `LEAD_ALLOWED_ORIGIN` | `https://pitermebel.com` |
   | `LEAD_CONSENT_VERSION` | `2026-09-29` (сверить с `LEGAL_VERSION` в `data/legal.ts`) |
   | `LEAD_CONSENT_TEXT` | полный точный текст согласия со страницы `/consent/` (не менее 100 символов) |
   | `YDB_DOCUMENT_ENDPOINT` | endpoint из шага 2 |
   | `YDB_LEADS_TABLE` | `leads` |
   | `LEAD_HASH_KEY` | случайная строка ≥ 32 символов (например, сгенерировать: `openssl rand -hex 32`); нигде не публиковать |
   | `POSTBOX_FROM` | адрес, созданный в шаге 3 |
   | `LEAD_NOTIFY_TO` | `piter.meb@yandex.ru` (сверить с владельцем) |

4. Кнопка **«Создать версию»**.
5. На странице функции → вкладка **«Обзор»** → блок **«Публичный доступ»** → включить переключатель. Теперь функцию можно вызывать по ссылке без авторизации.
6. Скопировать **ссылку на функцию**: `https://functions.yandexcloud.net/<идентификатор>`. Также её видно в поле «Ссылка для вызова» на вкладке «Обзор».

## Шаг 5. Прямая проверка функции (до подключения к сайту)

В Git Bash (заменить `<ID>` на идентификатор функции, URL можно взять из «Ссылка для вызова»):

```bash
curl -s -X POST "https://functions.yandexcloud.net/<ID>" \
  -H "Origin: https://pitermebel.com" \
  -F "submission_id=7e2b9c1a-3d4f-4e5a-9b8c-1d2e3f4a5b6c" \
  -F "Телефон=+79001234567" \
  -F "Тип мебели=Консультация" \
  -F "Пожелания=Тестовая заявка из инструкции" \
  -F "consent=true" \
  -F "consent_version=2026-09-29" \
  -F "consent_document=/consent/" \
  -F "consent_client_at=2026-10-04T12:00:00Z"
```

Ожидаемо: `{"success":true}`. Затем проверить:

1. **YDB**: база → «Навигация по объектам» → таблица `leads` → там запись `lead#7e2b9c1a…` с текстом согласия.
2. **Почта**: письмо на `piter.meb@yandex.ru` с темой «Заявка с сайта ПитерМебель …».
3. **Повтор**: тот же curl с тем же `submission_id` → снова `success`, дубля в YDB нет.
4. **Лимит**: четвёртая заявка с того же номера за 10 минут → HTTP 429.
5. **Журнал**: «Обзор» функции → «Логи» — там не должно быть телефона и текста заявки (обработчик логирует только сообщения об ошибках).

Если ответ `503` — смотреть логи функции: чаще всего неверный `YDB_DOCUMENT_ENDPOINT`, не создана таблица или Postbox-адрес не в том каталоге.

## Шаг 6. Маршрут на сайте `/api/leads` → функция

Сайт — статический экспорт; маршрут настраивается на хостинге. В `Caddyfile` (основной блок `https://pitermebel.com`, **до** последнего `handle` для страниц) добавить:

```caddyfile
    # Приём заявок: проксирование в Yandex Cloud Functions без редиректа
    handle /api/leads {
        rewrite * /<ID_ФУНКЦИИ>
        reverse_proxy https://functions.yandexcloud.net {
            header_up Host functions.yandexcloud.net
        }
    }
```

Заменить `<ID_ФУНКЦИИ>` на идентификатор из шага 4. Затем перечитать конфиг (`sudo systemctl reload caddy` на VPS) и проверить:

```bash
curl -i https://pitermebel.com/api/leads -X OPTIONS -H "Origin: https://pitermebel.com"
# ожидаемо: HTTP 204
```

Важно: браузер не должен получать редирект — форма шлёт POST именно на `/api/leads`. Если хостинг Timeweb App Platform не читает `Caddyfile` и не умеет проксировать путь — согласовать с поддержкой Timeweb или сменить схему размещения до включения формы (см. README, пункт 6).

## Шаг 7. Включение формы на сайте (после всей проверки)

Форма на сайте останется выключенной, пока не выполнено правило проекта из `LEGAL_SETUP.md` (согласие опубликовано, уведомление РКН подано, `approved` не установлен). Когда юридическая часть готова:

1. `data/legal.ts`: `PROCESSING_SETUP.approved = true`.
2. При сборке задать `NEXT_PUBLIC_LEAD_ENDPOINT=/api/leads`.
3. Пересобрать и опубликовать сайт.
4. Отправить тестовую заявку прямо с сайта и повторить проверки шага 5.
