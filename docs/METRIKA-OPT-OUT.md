# Яндекс.Метрика с отключением в футере

Решение владельца «ПитерМебель», 29.09.2026. Спецификация для сопровождения и переноса, не универсальное юридическое заключение.

## Поведение

- Новый посетитель: счётчик запускается после загрузки интерфейса автоматически, без баннера и предварительного подтверждения.
- В футере каждой страницы: сообщение о Метрике, ссылка на политику, настройка текущего браузера и кнопка «Отключить Яндекс.Метрику для меня». После отказа доступна кнопка включения.
- На странице политики тот же компонент и то же хранилище. Изменения синхронизируются между компонентами и вкладками.
- `pm_privacy_v1`: решение, дата, версия условий. Отказ не истекает через 180 дней и не сбрасывается при обновлении документа. Старая запись `analytics: false` сохраняет силу.
- Очистка данных сайта, новый браузер/профиль или удаление данных браузером означает отсутствие сохранённого выбора и автоматический запуск. Текст об этом опубликован.
- Если сохранение недоступно: выбор применяется в памяти до перезагрузки; посетитель видит объяснение. Не оставлять счётчик включённым после отказа из-за ошибки localStorage.
- Без JavaScript нет счётчика и фонового noscript-пикселя.
- Статус «включена» показывает настройку; блокировщики, сеть и ограничения браузера могут мешать загрузке. Не обещать учёт каждого визита.

## Состав аналитики

Счётчик `112318484`; `webvisor: false`, `clickmap: false`, `accurateTrackBounce: true`, `trackLinks: true`, `defer: true`, `ssr: true`. Явные SPA-просмотры без дублирования стартового просмотра; события контактов, успешной заявки и промо-окна. Скрипт — `tag.js?id=112318484`.

Источники, полные URL с параметрами, реферер, просмотры и длительность визитов сохраняются. Отсутствие Вебвизора/карты кликов не отключает историю просмотренных страниц. Значения полей формы не включаются в вызовы аналитики; нельзя помещать телефон/email/тексты заявок в URL и рекламные метки. ClientID/cookie и технические сведения не описывать как «данные вообще не собираются».

События: `zayavka` только после подтверждённой отправки, `contact_phone`, `contact_email`, `contact_vk`, `contact_telegram`, `contact_whatsapp`, `contact_max`, `boost_popup_show`, `boost_popup_close`, `boost_popup_click`.

Непроверенные настройки авторизованного кабинета: дополнительные настройки отслеживания/Advanced Matching, интеграции и теги, цели, сроки хранения. Их нужно сверить перед заявлением о полном соответствии аккаунта документам.

## Исправления, которые важно сохранить

1. Остановка — `destruct`, блокирование новых целей и очистка доступных записей `_ym`. Уже переданные запросы не отзываются.
2. Очередь `ym.a` очищается через `splice(0)`, а не заменяется массивом. Настоящая библиотека Яндекса оборачивает `push` существующей очереди; замена ломала повторный `init`.
3. Отказ до окончания загрузки SDK удаляет ещё не отправленные события. Поздняя загрузка не должна запустить счётчик вопреки выбору.
4. Storage-события обрабатываются только для ключа настройки или очистки хранилища: записи Метрики не запускают повторную синхронизацию.
5. Разрешения внешних фреймов Вебвизора/карт в Caddy удалены. Заголовок действует только после применения конфигурации на сервере.
6. Нижняя панель звонка на телефоне скрывается при показе нижней части футера, как возле других интерактивных блоков сайта: она не должна перекрывать кнопку отключения.

## Документы и перенос на другие сайты

Основные файлы: `lib/privacy.ts`, `lib/metrika.ts`, `components/YandexMetrika.tsx`, `components/PrivacySettings.tsx`, подключение в `Footer.tsx`, страницы `/privacy/` и `/analytics-consent/`, `LEGAL_SETUP.md`.

Для другого сайта заменить оператора, контакты, адреса, номер счётчика, URL, цели, сроки, реальных обработчиков и сведения о базах. Проверить сторонние сервисы заново. Не копировать согласие на заявки, сведения об инфраструктуре и реквизиты «ПитерМебель» без адаптации.

`isAnalyticsEnabled()` возвращает настройку запуска, а не факт явно выраженного согласия. Документы называют автоматический запуск прямо; не выдавать открытие страницы за зафиксированное нажатие «Разрешаю». Правовое основание такой обработки требует отдельной оценки; кнопка отказа и уведомление РКН его не заменяют. Не переносить утверждение, что отсутствие баннера признано законным или влечёт максимум предупреждение. Сохранить решение владельца об этой модели и не добавлять баннер/не отключать счётчик самостоятельно при последующих работах.

Редакции разделены: `PRIVACY_VERSION` / `PRIVACY_DATE` — политика и аналитика; `LEGAL_VERSION` / `LEGAL_DATE` — отдельное согласие на заявку. При изменении последнего обновить сервер, архив текста/хеша и форму согласованно.

Отключение не обещает удаления старой статистики. У посетителя остаётся канал обращения к оператору. Точечное удаление в сервисе и срок хранения статистики подтвердить у Яндекса. ClientID — ориентир для соответствующего браузера, а не удостоверение личности.

Для реальных заявок остаётся `FORM_SETUP.md` и инструкция выбранного обработчика. Опубликовать реальные сведения и настроить хранение/удаление до включения приёма. Уведомление РКН заполнять фактическими данными; юридический адрес Яндекса не подставлять вместо адреса базы/ЦОД.

## Проверка

```text
npm run build
npm run test:privacy
npm run test:seo
npm run test:seo-browser
npm run test:metrika-browser
```

Последняя проверка скачивает только публичную библиотеку конкретного счётчика. Страницы обслуживаются из локального `out/`, ВСЕ запросы SDK перехватываются и получают тестовый ответ; визиты не отправляются Яндексу. Для офлайн-запуска указать `PM_METRIKA_TAG_PATH` на сохранённый `tag.js?id=112318484`, а не на общий скрипт без ID. Это проверяет жизненный цикл реального SDK, но не доставку в кабинет и не его закрытые настройки.

Сценарии: свежий визит; отключение из футера; перезагрузка/навигация после отказа; включение без перезагрузки; старая запись отказа; две вкладки; ошибка сохранения; отказ во время загрузки SDK; остановка таймера точного отказа; отсутствие счётчика без JS; ширины 320, 390 и 1440 px.

Результат 29.09.2026: сборка прошла (52 страницы); `test:privacy` — 9/9, `test:seo` — 6/6; `test:seo-browser` и `test:metrika-browser` прошли. Последний тест использовал настоящую публичную библиотеку счётчика с перехватом отправки статистики. Проверены доступность кнопки на телефоне и отсутствие перекрытия нижней панелью. Отчёт и снимки — `output/privacy-2026-09-29/`, включая `metrika-integration.json` и `footer-enabled-390.png`. Проверка выполнена на локальной сборке, изменения не опубликованы.
